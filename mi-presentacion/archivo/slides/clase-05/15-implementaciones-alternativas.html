02 · Implementación y casos de aplicación

Tabla en memoria y punteros a función

Dos alternativas al switch. Ambas cuestan más de escribir y solo se justifican cuando el número de estados hace ilegible la selección múltiple.

Tabla de transiciones en memoria

La tabla de diseño se traslada a un arreglo de estructuras. Buscar la fila que corresponde al par estado-evento sustituye al switch. 

struct Fila {
  Estado desde; Evento ev; Estado hasta; void (*accion)();
};
const Fila TABLA[] PROGMEM = {
  {Estado::VERDE, Evento::PULSADOR,   Estado::AMBAR, arrancarAmbar},
  {Estado::AMBAR, Evento::VENCE_TEMP, Estado::ROJO,  arrancarPaso },
};

Ventaja: la tabla del diseño y la del código son el mismo objeto, de modo que no pueden divergir. Con PROGMEM reside en Flash y no ocupa SRAM.

Punteros a función por estado

Cada estado es una función, y una variable de tipo puntero apunta a la del estado activo. La transición reasigna ese puntero. 

void (*estadoActual)(Evento);

void enVerde(Evento e) {
  if (e == Evento::PULSADOR) estadoActual = enAmbar;
}
void loop() { estadoActual(leerEvento()); }

Ventaja: cada estado queda aislado en su propia función, lo que facilita añadir estados sin tocar los existentes. Costo: el flujo deja de leerse en un solo punto y la traza de retorno resulta menos informativa.

Cuál se elige

El switch hasta unos diez estados, que cubre todos los ejemplos de este curso. La tabla en memoria cuando el número de filas crece y conviene generarla o revisarla como dato. Los punteros a función cuando cada estado tiene lógica extensa propia. Adoptar la tercera forma en un problema de tres estados añade indirección sin resolver ningún problema real.
