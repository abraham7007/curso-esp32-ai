02 · Comunicación y sincronización

Acceso concurrente a un recurso compartido

Definición

Hay condición de carrera cuando el resultado depende del orden en que se intercalan dos tareas. Una operación que en el código fuente parece indivisible se traduce en varias instrucciones, y el planificador puede interrumpir entre ellas.

Por qué contador++ no es indivisible

Se compila en tres instrucciones: leer el valor de memoria a un registro, incrementar el registro y escribir el resultado. Si dos tareas leen antes de que ninguna escriba, ambas escriben el mismo valor y un incremento se pierde.

volatile no resuelve una condición de carrera. Obliga al compilador a releer la variable de memoria, pero no hace indivisible la secuencia de tres instrucciones. Sirve para que el compilador no cachee el valor, no para excluir accesos simultáneos.

Así no dos tareas, un contador 
volatile uint32_t cuenta = 0;   // no basta

void tareaA(void *) { for(;;) cuenta++; }
void tareaB(void *) { for(;;) cuenta++; }

// Tras 1 000 000 de incrementos por tarea,
// cuenta vale menos de 2 000 000.
[CARRERA] esperado=2000000 obtenido=1338472 perdidos=661528 (33%) [CARRERA] mismo nucleo: esperado=2000000 obtenido=1994310 perdidos=0.3% [MUTEX] esperado=2000000 obtenido=2000000 perdidos=0

La segunda línea es la que hace peligroso este fallo: con ambas tareas en el mismo núcleo se pierde el 0,3 %, y el programa parece correcto en el ensayo. El error aparece al repartirlas entre núcleos, meses después.
