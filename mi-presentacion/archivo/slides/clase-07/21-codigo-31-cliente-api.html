La hora del código Ejemplo 31

Cliente de una API pública con los cuatro fallos diferenciados

Sobre el proyecto. Consultar una API pública cada cinco minutos y extraer tres campos. Cada fallo se clasifica en una de las cuatro causas de la lámina anterior y cada una recibe su propio tratamiento, porque no todas se arreglan reintentando.

Conceptos clave

Un filtro de deserialización indica de antemano qué campos interesan, de modo que el resto del documento no llega a ocupar memoria: leyendo de http.getStream() ni siquiera se guarda la respuesta entera. Los códigos 4xx señalan un error del cliente (clave inválida, ruta inexistente) y repetir la petición no los corrige; los 5xx y los tiempos agotados sí admiten reintento. El dato caducado es el último valor válido con su timestamp, conservado pero señalado.

Prompt para el asistente

1. Proyecto. Crea un proyecto nuevo de PlatformIO para la placa esp32dev con el framework Arduino. 2. Firmware. Consulta una API pública cada 300000 ms y extrae tres campos con un filtro de ArduinoJson leyendo de http.getStream(). Clasifica cada fallo en SIN_RED, SIN_INTERNET, SERVIDOR_MUDO o HTTP_ERROR y aplica el tratamiento de la tabla: los 4xx no se reintentan. El plazo de espera de la petición es de 8000 ms. Conserva el último dato válido con su timestamp y márcalo como caducado si supera los 900 s. La clave va en credenciales.h, excluido del control de versiones. Emite a 115200 baudios. 3. Simulación. Añade la simulación de Wokwi con los cuatro LED en los GPIO indicados. 4. Diagramas. Entrega dos en Excalidraw. El diagrama de flujo de una consulta completa, desde la petición hasta la actualización del dato o su marcado como caducado. Y el árbol de decisión que lleva de una petición fallida a cada una de las cuatro causas, con la comprobación que las distingue.

Análisis

La cuarta línea de fallo es la que cambia el comportamiento: ante un 401 la acción es no reintentar. Un token caducado no se arregla repitiendo la petición cada cinco minutos durante meses, y esa es la regla que más energía ahorra en un equipo con batería. La última línea muestra la otra decisión: el dato no se borra, se marca caducado, para que el equipo siga sirviendo sin mentir sobre la antigüedad de lo que muestra.
