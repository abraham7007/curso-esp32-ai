02 · Protocolo HTTP y APIs REST

Extracción de campos de una respuesta que no cabe en memoria

El problema

Un pronóstico de cinco días son unos 200 kB de JSON, y el ESP32 dispone de unos 200 kB de memoria libre. Reservar la respuesta completa y su representación en memoria es imposible, aunque solo interesen tres campos.

En el código

ArduinoJson admite un filtro: un documento que describe qué campos conservar. La biblioteca recorre el flujo conforme llega y descarta el resto sin llegar a reservarlo. Se pasa con DeserializationOption::Filter(filtro).

Se lee del flujo, no de una cadena

La clave es pasar http.getStream() en vez de http.getString(). Con la cadena, los 200 kB ya están en memoria antes de que el filtro intervenga y el dispositivo se ha reiniciado.

Así sí filtro sobre el flujo 
JsonDocument filtro;
filtro["main"]["temp"] = true;      // solo estos tres
filtro["main"]["humidity"] = true;
filtro["name"] = true;

JsonDocument doc;
deserializeJson(doc, http.getStream(),
                DeserializationOption::Filter(filtro));

float t = doc["main"]["temp"];      // 220 bytes en memoria
[HTTP] respuesta: 204812 bytes [JSON] sin filtro: reserva estimada 268 kB -> sin memoria, reinicio [JSON] con filtro: reserva real 220 bytes -> 3 campos extraidos [MEM] libre tras deserializar: 198 440 bytes
