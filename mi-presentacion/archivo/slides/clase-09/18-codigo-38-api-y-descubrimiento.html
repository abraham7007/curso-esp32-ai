La hora del código Ejemplo 38

API del dispositivo con nombre local y factory reset

Sobre el proyecto. Publicar la API completa de la lámina anterior y hacer al equipo localizable por nombre. La lectura de configuración nunca devuelve la contraseña, toda escritura responde con la configuración resultante, y el restablecimiento exige confirmación explícita.

Conceptos clave

Un punto de acceso de la API es un método más una ruta; el método dice si la operación lee o escribe. Responder con la configuración resultante en lugar de con un acuse vacío ahorra una segunda petición y elimina la duda de qué quedó guardado. El código 409 significa que la petición es válida pero choca con el estado actual: aquí se usa para exigir confirmación antes de una operación que no se puede deshacer.

Prompt para el asistente

1. Proyecto. Crea un proyecto nuevo de PlatformIO para la placa esp32dev con el framework Arduino, ESPAsyncWebServer, ArduinoJson y Preferences. 2. Firmware. Publica el nombre local con mDNS y anuncia el servicio HTTP. Implementa GET /api/info, GET /api/estado, GET /api/config, POST /api/config y POST /api/reset. La lectura de configuración devuelve el nombre de la red pero nunca la contraseña. Toda escritura responde con la configuración resultante, no con un acuse vacío. El restablecimiento responde 409 si la petición no lleva confirmación explícita, y al ejecutarse registra por separado qué borra y qué conserva. Emite a 115200 baudios cada petición con su código. 3. Simulación. Añade la simulación de Wokwi con el pulsador en el GPIO 4 y el LED en el GPIO 25. 4. Diagramas. Entrega dos en Excalidraw. El diagrama de flujo del restablecimiento, con la comprobación de la confirmación y la separación entre lo que se borra y lo que se conserva. Y la tabla de la API, una fila por punto de acceso: método, ruta, qué devuelve y si modifica el dispositivo.

Diagrama de conexión

El ESP32 lee un pulsador de restablecimiento en el GPIO 4 con INPUT_PULLUP y enciende un LED de confirmación en el GPIO 25 con resistencia de 220 Ω, que parpadea durante la cuenta atrás.

Análisis

Las dos líneas de /api/reset: la primera responde 409 y no borra nada. Esa negativa es lo que impide que una petición repetida o perdida deje el equipo en blanco, y es la idempotencia de la sesión 8 aplicada a algo que no se puede deshacer. Mirar además la línea de GET /api/config: si en la traza propia apareciera la contraseña, cualquiera dentro de la red la tendría con una sola petición.
