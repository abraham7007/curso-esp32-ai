01 · Servidor web embebido

Recursos servidos desde el sistema de archivos, no desde el código

HTML como cadena en el código

Cambiar un rótulo obliga a recompilar y regrabar. El HTML ocupa espacio en la partición de aplicación y hay que escapar cada comilla.

Recursos en el sistema de archivos

Se sustituye el archivo y basta. Los recursos viven en su propia partición y se editan con las herramientas habituales de la web.

En el código

Los archivos se colocan en data/ y se suben con la orden de sistema de archivos de PlatformIO, que es distinta de la de grabar el firmware: son dos particiones y dos operaciones. Olvidar la segunda deja un servidor que responde 404 a todo.

Sin acceso a internet

El dispositivo debe presentar su interfaz aunque no haya internet: durante el provisioning (aprovisionamiento) no lo hay por definición. Toda biblioteca externa se incorpora al sistema de archivos; una hoja de estilos traída de un servicio ajeno deja el portal sin formato justo cuando más importa.

data/www/index.htmlpágina del panel
data/www/estilo.csscomprimido con gzip
data/www/panel.jssin dependencias externas
src/main.cpprutas y lógica, sin HTML
$ pio run --target uploadfs # sistema de archivos $ pio run --target upload # firmware [FS] LittleFS montado usado=48 kB de 1408 kB

La compresión con gzip se sirve tal cual: el navegador la descomprime y el dispositivo ahorra el espacio y el tiempo de transmisión.
