Configuración del panel en la consola de Blynk

Hacer los cinco pasos en vivo y en este orden, antes de escribir el firmware: el firmware del ejemplo 19 no crea nada en la nube y usa lo que aquí se nombra, los pines V0 y V1 y las tres credenciales del dispositivo.

Pregunta de predicción: si el datastream V1 no se crea, ¿qué ocurre cuando el ESP32 envía la temperatura a V1? Respuesta: el ESP32 sigue conectado, pero el valor no llega al Gauge; el servidor lo descarta porque el pin no existe en la plantilla.

V0 como Integer de 0 a 1 encaja con un LED (apagado o encendido); V1 como Double conserva el decimal. Los nombres de la consola están en inglés y cambian con las versiones; si un botón tiene otro nombre, el paso es el mismo. No proyectar el token real.

Para estudiar

En la práctica

Activar Developer Mode en el perfil para ver Developer Zone. En el paso 3, arrastrar cada widget desde el Widget Box y elegir su datastream en el engranaje. En el paso 5, copiar secrets.example.h como secrets.h y pegar las tres líneas de Device Info; el firmware las lee antes de cargar la biblioteca Blynk.

Dónde aparece

Ejemplo 19 (lámina siguiente).

Errores frecuentes

  • Dejar un widget sin datastream asignado, con lo que el widget no cambia.
  • Crear V1 como Integer, que descarta el decimal.
  • Pegar el token de otro dispositivo (respuesta «Invalid auth token»).
  • Usar el Template ID de otra plantilla, que no corresponde al panel configurado.
