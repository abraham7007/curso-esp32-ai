02 · Comunicación y sincronización

Deadlock por orden de adquisición

Caso mínimo

Dos tareas y dos mutex. La tarea A toma el bus y pide la pantalla; la tarea B toma la pantalla y pide el bus. Cada una retiene lo que la otra necesita, y ninguna puede avanzar ni liberar.

Regla que lo elimina

Fijar un orden global de adquisición y respetarlo en todo el programa: primero el bus, después la pantalla, siempre. Con un orden único el deadlock (interbloqueo) es imposible por construcción, sin necesidad de detectarlo ni de recuperarse de él.

Red de seguridad

Tomar todo mutex con un plazo máximo en vez de portMAX_DELAY. No corrige el diseño, pero convierte un bloqueo silencioso en un error registrado que señala qué recurso y qué tarea intervinieron.

Así no órdenes de adquisición opuestos 
void tareaA(void *) {
  xSemaphoreTake(mBus, portMAX_DELAY);
  xSemaphoreTake(mPantalla, portMAX_DELAY);
  ...
}
void tareaB(void *) {
  xSemaphoreTake(mPantalla, portMAX_DELAY);
  xSemaphoreTake(mBus, portMAX_DELAY);   // orden inverso
  ...
}
[BLOQUEO] tarea=A estado=Blocked espera=mPantalla retiene=mBus [BLOQUEO] tarea=B estado=Blocked espera=mBus retiene=mPantalla [WDT] Task watchdog got triggered. The following tasks did not reset: A, B

El deadlock no produce ningún mensaje propio: se manifiesta como un aviso del watchdog, que señala el síntoma y no la causa.
