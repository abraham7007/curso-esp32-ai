setup() y loop() como máquina de estados implícita

Definición

El par setup()/loop() ya describe un sistema con un estado inicial y un ciclo que se repite indefinidamente. Cuando el comportamiento depende de condiciones acumuladas, ese estado existe igualmente, pero aparece disperso en variables booleanas sueltas y en las ramas que las leen.

setup() fija el estado inicial · se ejecuta una vez
loop() ↻ evalúa las condiciones y decide la transición
Del problema a la solución

Nombrar explícitamente los estados y las transiciones es el contenido de la Sesión 5. Identificar aquí que el problema ya existe (que el estado está, solo que sin nombre) es lo que hace evidente por qué hace falta.

src/main.cpp · control de una salida por nivel y por pulsador Así no 
bool encendido = false;   bool esperando = false;
bool modoAuto  = false;   bool alarma    = false;

void loop() {
  if (modoAuto) {
    if (!esperando) {
      if (nivel > UMBRAL) {
        encendido = true;  esperando = true;  t0 = millis();
      } else if (alarma) {
        encendido = false;
      }
    } else if (millis() - t0 >= 3000) {
      esperando = false;
      if (!alarma) encendido = !encendido;
    }
  } else if (boton.huboFlanco()) {
    encendido = !encendido;
    if (encendido && alarma) esperando = true;
  }
  digitalWrite(SALIDA, encendido);
}
Cuatro banderas independientes admiten 2⁴ = 16 combinaciones; solo cinco corresponden a situaciones reales del sistema. Las once restantes no están prohibidas por nada: aparecen en cuanto una rama olvida actualizar una bandera, y no hay dónde comprobar que no ocurren.
