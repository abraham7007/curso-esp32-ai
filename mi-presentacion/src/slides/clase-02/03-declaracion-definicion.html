01 · Organización del proyecto

Declaración frente a definición

La declaración anuncia la firma; la definición aporta el cuerpo. Van en archivos distintos porque las consume gente distinta de la cadena de construcción.

lib/Led/Led.h Interfaz pública · contrato 
#include <Arduino.h>

class Led {
public:
  explicit Led(uint8_t pin);
  void begin();
  void on();  void off();
private:
  uint8_t pin_;
};
lib/Led/Led.cpp Unidad de traducción · privado 
#include "Led.h"

Led::Led(uint8_t pin) : pin_(pin) {}

void Led::begin() { pinMode(pin_, OUTPUT); }

void Led::on()  { digitalWrite(pin_, HIGH); }void Led::off() { digitalWrite(pin_, LOW); }
1 · Preprocesador Copia Led.h dentro de Led.cpp y dentro de main.cpp.
→
2 · Compilador Traduce cada unidad por separado: main.o y Led.o, sin verse una a otra.
→
3 · Enlazador (linker) Casa cada símbolo pendiente con su definición y produce firmware.bin.
[LINK ERROR] undefined reference to 'Led::toggle()' in main.cpp.o cpp-linker: error: ld returned 1 exit status

Un método declarado en el .h y nunca definido en el .cpp compila sin una queja: al compilador le basta la firma. Quien falla es el enlazador, que busca el cuerpo y no lo encuentra.
