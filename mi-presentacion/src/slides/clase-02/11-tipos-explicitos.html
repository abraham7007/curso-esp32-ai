03 · Tipos, constantes y ámbito

Tipos de datos de tamaño específico

Definición

uint8_t, int16_t y uint32_t declaran el tamaño exacto en bits del dato. int no garantiza el mismo tamaño entre arquitecturas: son 4 bytes en el ESP32 y 2 bytes en un AVR de 8 bits, con el mismo código fuente.

Anatomía del nombre
u
Unsigned: sin signo, solo valores ≥ 0.
int
Integer: número entero, sin decimales.
8
8 bits: ocupa exactamente 1 byte.
_t
Type definition: sufijo de C para un nombre de tipo.
Ejemplo

Un contador de pulsaciones que nunca pasa de 200 cabe en uint8_t: 1 byte. Declararlo int gasta 4 bytes y desperdicia 3. En una variable suelta es irrelevante; en un arreglo de 1 000 muestras son 1 KB frente a 4 KB de los 520 KB de SRAM.

En la práctica

Los tipos vienen de <stdint.h>, ya incluido por el núcleo de Arduino: no hace falta añadir nada. Regla del curso: el tipo se elige por el rango real del dato, y size_t para índices y tamaños.

Tipo Tamaño Rango representable
uint8_t 1 byte 0 … 255
int8_t 1 byte −128 … 127
uint16_t 2 bytes 0 … 65 535
int16_t 2 bytes −32 768 … 32 767
uint32_t 4 bytes 0 … 4 294 967 295
int 4 bytes en el ESP32 fijado por la arquitectura, no por el código
1 000
Arreglo de uint8_t 1,0 KB
Arreglo de int 3,9 KB
SRAM desperdiciada 2,9 KB
Fracción de los 520 KB de SRAM 0,56 %

Ambos arreglos guardan exactamente el mismo dato, pulsaciones entre 0 y 200, y producen la misma lectura. La diferencia es la memoria ocupada: el factor 4 entre uint8_t e int es constante, así que crece con el número de muestras.
