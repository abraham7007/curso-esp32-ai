01 · Organización del proyecto

Función del archivo principal

main.cpp coordina módulos: los instancia, los inicializa y los hace avanzar. No ejecuta la lógica de ninguno.

Monolítico · todo en un archivo src/main.cpp acumula, en este orden y sin frontera entre ellos:
→
variables globales · lógica de lectura · temporizaciones · control de la salida
Orquestador · delega src/main.cpp instancia, llama a begin() y a update(). Nada más.
→
Led
Boton
Sensor
src/main.cpp · más de 100 líneas Así no 
int pinLed = 2;
int estadoBtn = 0;

void setup() { pinMode(2, OUTPUT); pinMode(4, INPUT); }
void loop()  { if (digitalRead(4)) digitalWrite(2, HIGH); ... }
El pin aparece como número suelto en cuatro sitios. Añadir un segundo periférico duplica el patrón en vez de reutilizarlo.
src/main.cpp · menos de 25 líneas Así sí 
Led   led(2);
Boton btn(4);

void setup() { led.begin(); btn.begin(); }
void loop()  { btn.update(); if (btn.wasPressed()) led.toggle(); }
Cada pin se declara una vez, junto al objeto que lo posee. Añadir un periférico son dos líneas más.
Opción adoptada

Se adopta el segundo, y con una medida que se puede comprobar: menos de 25 líneas en src/main.cpp, con el mismo comportamiento observable que la versión monolítica. Detrás está el principio de responsabilidad única (SRP, single responsibility principle): cada módulo tiene una razón para cambiar, y el punto de entrada no tiene ninguna propia.
