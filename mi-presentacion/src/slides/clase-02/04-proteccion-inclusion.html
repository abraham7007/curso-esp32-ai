Include guard

Mecanismo que impide que un encabezado se inserte más de una vez en la misma unidad de traducción. Basta con que dos módulos incluyan el mismo .h para que el preprocesador lo copie dos veces.

Punto de partida src/main.cpp incluye "Led.h" y "Tablero.h".
→
Vía directa El preprocesador pega class Led. Copia 1.
→
Vía indirecta Tablero.h también incluye Led.h, y se vuelve a pegar. Copia 2.
→
Una sola unidad class Led queda declarada dos veces en el mismo archivo expandido.
lib/Led/Led.h Así no 
#include <Arduino.h>

class Led { ... };   // el cuerpo no cambia
Cada inclusión reexpande el archivo entero. Dos rutas hasta él dejan dos declaraciones idénticas en la misma unidad de traducción.
lib/Led/Led.h Así sí 
#ifndef LED_H#define LED_H
#include <Arduino.h>

class Led { ... };   // el cuerpo no cambia
#endif  // LED_H
La segunda vez, LED_H ya está definido y el preprocesador omite el bloque entero. El nombre del macro va en mayúsculas y debe ser único en todo el proyecto.
Alternativa moderna

#pragma once en la primera línea hace lo mismo sin inventar un nombre de macro. El compilador de la cadena de herramientas lo admite.

Se incumple la regla de definición única (ODR, one definition rule): una clase admite una sola definición por unidad de traducción. Falla al compilar, nunca en ejecución.
