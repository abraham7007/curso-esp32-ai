Plantilla, dispositivo y token en el modelo de Blynk

Plantilla (template): datos y panel comunes a un tipo de equipo. Dispositivo: instancia creada desde la plantilla. Token (auth token): identificador único que autentica a cada dispositivo.

Recorrer de izquierda a derecha. La plantilla se define una vez: qué datos intercambia el equipo y cómo se ven en el panel. Cada dispositivo es una instancia de esa plantilla, con su placa y su token.

Pregunta de predicción: se añade a la plantilla un dato nuevo, la humedad. ¿Hay que repetir el cambio en los tres dispositivos? Respuesta: no. Los tres heredan la plantilla y reciben el cambio a la vez; lo que sí hay que actualizar es el firmware de cada placa para que envíe ese dato.

Paso 1: aclarar que la biblioteca de Blynk no habla MQTT. Usa un protocolo propio sobre TCP con TLS, con las mismas ideas del bloque 3: la placa abre y mantiene la conexión con un ping periódico; el servidor guarda el último valor de cada dato y lo entrega al reconectar; si deja de recibir el ping, marca el dispositivo «Offline». Un comando enviado con la placa desconectada no se encola para entregarse después, como en QoS 0: solo queda el último valor, que la placa recupera al sincronizar (lámina 17). Para equipos que ya hablan MQTT, Blynk ofrece además un broker propio.

Paso 2: el token es la credencial del dispositivo; quien lo tiene lee sus datos y le envía órdenes. Por eso no se proyecta el real (TU_TOKEN_AQUI). El detalle está en «Para estudiar».

En la práctica

Consola: Developer Zone › My Templates (plantilla) y Devices › New Device › From template (dispositivo). «Device Info» muestra Template ID, Template name y Auth token. En el ejemplo 19 van en include/secrets.h, listado en .gitignore; se versiona solo secrets.example.h con TU_TOKEN_AQUI. La cabecera BlynkSimpleEsp32_SSL.h conecta por el puerto 443 con TLS; la variante sin SSL usa el 80 y envía el token legible. Un token subido a un repositorio público queda en el historial de git: borrarlo del archivo no basta; se borra el dispositivo y se crea otro desde la plantilla, que recibe un token nuevo.

API MQTT de Blynk: broker blynk.cloud, puertos 1883 y 8883 (TLS), usuario device y contraseña igual al token; no admite dos clientes simultáneos con el mismo token (docs.blynk.io › Device MQTT API › Authentication).

Errores frecuentes

  • Grabar dos placas con el mismo token, que se desconectan entre sí (lámina 20).
  • Añadir secrets.h al .gitignore después de subirlo, cuando git ya lo sigue.
