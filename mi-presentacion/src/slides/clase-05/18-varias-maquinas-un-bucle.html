02 · Implementación y casos de aplicación

Coexistencia de máquinas independientes en el mismo bucle

Principio

Cada actividad con su propio ritmo lleva su propia máquina, con su variable de estado y su timestamp. El bucle las evalúa todas en cada iteración, y ninguna bloquea a las demás.

Ejemplo

Un equipo con tres actividades: muestrear un sensor cada 100 ms, parpadear un indicador cada 500 ms y atender un pulsador con pulsación larga. Tres máquinas, tres variables de estado, un solo bucle.

El límite aparece cuando dos actividades tienen requisitos temporales incompatibles: una necesita responder en 1 ms y otra ocupa 40 ms por iteración. Ahí el bucle único deja de bastar, y esa es la condición que justifica las tareas de la sesión 6.

Así sí tres máquinas, un bucle 
void loop() {
  uint32_t ahora = millis();
  maquinaSensor(ahora);     // estado propio, marca propia
  maquinaIndicador(ahora);
  maquinaPulsador(ahora);
}
// Cada función es un switch sobre SU variable de estado.
// Ninguna espera: todas retornan en microsegundos.
Sensor
REPOSO ⇄ MIDIENDO · periodo 100 ms
Indicador
ENCENDIDO ⇄ APAGADO · periodo 500 ms
Pulsador
SUELTO → PULSADO → LARGA · umbral 1200 ms

Las tres máquinas comparten el bucle pero no comparten estado: la pulsación larga no altera el periodo de muestreo.
