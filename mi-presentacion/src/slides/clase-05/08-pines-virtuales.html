03 · Pines virtuales

Pines virtuales entre widgets y funciones del firmware

Un pin virtual (V0, V1) es el nombre con el que un datastream llega al firmware, ajeno a los GPIO. La librería entrega cada orden a una función BLYNK_WRITE; cada dato sale con virtualWrite.

V0: panel → placa
V1: placa → panel

Pregunta de predicción: el firmware no consulta en ningún momento el estado del Switch. ¿Quién ejecuta la función asociada a V0, y cuándo? Recoger respuestas antes de pulsar «Desde el inicio».

Respuesta: la librería, dentro de Blynk.run, cuando llega por la conexión abierta una trama para V0. Recorrer los 8 pasos. Arriba (pasos 1 a 4): widget → datastream V0 → trama HARDWARE con «vw 0 1» → función BLYNK_WRITE de V0 → GPIO 15 → LED. Abajo (5 a 8): una tarea del temporizador obtiene la temperatura cada 30 s y virtualWrite la envía a V1, que recorre el camino inverso hasta el Gauge.

El nombre V0 no tiene relación con el GPIO 15: el vínculo lo escribe el programador dentro de la función. El mismo V0 podría mover un relé o un servo sin cambios en el panel. En la trama, los campos del cuerpo van separados por un byte 0 (lámina 7).

Para estudiar

En la práctica

Una función BLYNK_WRITE por cada pin virtual que recibe órdenes; el valor llega como parámetro y se lee como entero, decimal o texto según el tipo del datastream. virtualWrite recibe el pin y el valor que se envía. El datastream fija tipo y rango (V0 entero 0–1, V1 double 0–50 °C, lámina 9).

Dónde aparece

Ejemplo 19: V0 enciende el LED del GPIO 15; V1 recibe la temperatura cada 30 s.

Errores frecuentes

  • Escribir BLYNK_WRITE dentro del loop, cuando se define fuera, como función independiente.
  • Enviar con virtualWrite en cada vuelta del loop (inundación).
  • Usar en el código un pin virtual que no existe como datastream.
