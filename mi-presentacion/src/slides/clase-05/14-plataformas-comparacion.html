04 · Plataformas de IoT

Criterios de comparación entre plataformas de IoT

Leer la tabla por columnas: cada columna es un criterio. Alojamiento decide quién instala y mantiene el servidor; protocolos, qué tiene que hablar el firmware; licencia, costo y dependencia, cuánto cuesta cambiar de proveedor más adelante. «Propio» indica un protocolo definido por el fabricante.

Tres grupos: Blynk, servicio alojado orientado a la app móvil; ThingsBoard, Node-RED y Home Assistant, instalables en un equipo propio, por ejemplo una Raspberry Pi; AWS IoT Core y Azure IoT Hub, nubes industriales que solo existen como servicio gestionado.

Pregunta de predicción: un proyecto de domótica sin conexión a Internet estable, ¿qué columnas descartan a Blynk y a las nubes industriales? Respuesta: alojamiento y dependencia. Las tres exigen llegar a un servidor del proveedor; Home Assistant o Node-RED funcionan en la red local.

Paso 1: el criterio y la opción adoptada. Blynk se elige para el laboratorio porque no requiere servidor propio y trae app móvil; la contrapartida es la cuota y la dependencia del proveedor (lámina 18).

Para estudiar

Datos verificados (octubre de 2026)

  • Blynk: protocolo propio en la biblioteca del firmware (licencia MIT); API HTTPS y API MQTT del dispositivo (blynk.cloud, 8883 con TLS). El servicio es propietario; la instalación en servidores propios solo existe en el plan empresarial (Enterprise), con precio a medida.
  • ThingsBoard: MQTT, MQTT Sparkplug B, HTTP, CoAP (RFC 7252), LwM2M (gestión de dispositivos sobre CoAP) y SNMP (gestión de equipos de red). Hasta la versión 4.3, Apache 2.0. Desde la 4.4, BUSL 1.1 (Business Source License): código público y uso comercial gratuito hasta 100 dispositivos en un servidor; cada versión pasa a Apache 2.0 a los cuatro años.
  • Node-RED: Apache 2.0 (OpenJS Foundation); nodos de red MQTT, HTTP, WebSocket, TCP y UDP.
  • Home Assistant: Apache 2.0; MQTT con un broker externo (Mosquitto) y la API nativa de ESPHome, un firmware abierto para ESP32 que habla con Home Assistant por TCP.
  • AWS IoT Core: MQTT 3.1.1 y 5 con QoS 0 y 1 (sin QoS 2), MQTT sobre WebSocket y HTTPS solo para publicar.
  • Azure IoT Hub: soporte parcial de MQTT; además AMQP (protocolo de mensajería de OASIS), ambos también sobre WebSocket, y HTTPS. Se paga por nivel y unidades de capacidad diaria; hay un nivel gratuito de prueba.

En la tabla, «HTTP» incluye HTTPS y «abierta con límite» resume la BUSL 1.1 de ThingsBoard.

Errores frecuentes

  • Elegir por la lista de funciones sin mirar alojamiento y licencia.
  • Suponer que una nube industrial con MQTT acepta todo el estándar: AWS no admite QoS 2.
