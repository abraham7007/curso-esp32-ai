Configuración del panel antes del firmware

Por qué antes. El firmware solo usa lo que aquí se nombra: los pines V0 y V1 y las tres credenciales del dispositivo.

Hacer los cinco pasos en vivo y en este orden. El firmware del Ejemplo 19 no crea nada en la nube; usa lo que ya existe.

Pregunta de predicción: si el datastream V1 no se crea, ¿qué ocurre cuando el ESP32 envía la temperatura a V1?

Respuesta: el ESP32 sigue conectado, pero el valor no llega al Gauge; el servidor lo ignora porque el pin no existe en la plantilla.

V0 como Integer de 0 a 1 encaja con un pin digital (apagado o encendido); V1 como Double guarda el decimal. Los nombres de la consola están en inglés y cambian con las versiones; si un botón tiene otro nombre, el paso es el mismo. No proyectar el token real; la lámina muestra el marcador TU_TOKEN_AQUI.

Para estudiar

En la práctica

Activar Developer Mode en el perfil para ver Developer Zone. La plantilla define datastreams y paneles para todos sus dispositivos; cada dispositivo tiene su propio token. Copiar secrets.example.h como secrets.h y pegar las tres líneas.

Dónde aparece

Ejemplo 19 (lámina siguiente).

Errores frecuentes

  • Dejar un widget sin datastream asignado; el widget no cambia.
  • Crear V1 como Integer, que descarta el decimal.
  • Pegar el token de otro dispositivo (respuesta «Invalid auth token»).
  • Usar el Template ID de otra plantilla, que no corresponde al panel configurado.
