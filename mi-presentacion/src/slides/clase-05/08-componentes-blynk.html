03 · Plataforma Blynk

Plantilla, dispositivo y token en la consola de Blynk

La plantilla (template) describe un tipo de equipo: sus datos y su panel. Cada dispositivo se crea desde ella y recibe su propio token, la clave que identifica a esa placa.

Recorrer de izquierda a derecha. La plantilla se define una vez: qué datos tiene la estación (el LED, que recibe órdenes, y la temperatura, que se envía) y cómo se ven en el panel. Cada aula es un dispositivo creado desde esa plantilla.

Pregunta de predicción: se añade a la plantilla un dato nuevo, la humedad. ¿Hay que repetir el cambio en las tres aulas? Respuesta: no. Los tres dispositivos comparten la plantilla y reciben el cambio a la vez; lo que sí hay que actualizar es el firmware de cada placa para que envíe ese dato.

Paso 2: el token funciona como la llave del dispositivo. Quien lo tiene se conecta a Blynk como esa placa; por eso cada placa lleva el suyo y no se proyecta nunca el real (la lámina muestra TU_TOKEN_AQUI). Su protección es la lámina 15.

Para estudiar

En la práctica

Consola de Blynk: Developer Zone › My Templates (plantilla) y Devices › New Device › From template (dispositivo). En «Device Info» aparecen los tres valores que necesita el firmware: Template ID (TMPLxxxxxxxx), Template name (ESP32 PIT 2026) y Auth token (TU_TOKEN_AQUI). Dónde se guardan: lámina 15.

Dónde aparece

Ejemplo 19: una plantilla y un dispositivo, el del aula 1. El plan gratuito admite 5 dispositivos.

Errores frecuentes

  • Copiar el token de otro dispositivo o de otra plantilla: el panel queda vacío o mezcla datos.
  • Grabar dos placas con el mismo token, que se desconectan entre sí (lámina 16).
