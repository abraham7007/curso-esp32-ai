Qué debe hacer

Compilar el mismo programa sin y con WiFi.begin() y comparar el informe de RAM y Flash de cada construcción.

Montaje

El del Ejemplo 01: LED con 220 Ω en el GPIO 2. El enlazador da la medida; el circuito no interviene.

ESP32-WROOM-32 LED 220 Ω

Salida esperada · terminal de pio run

$ pio run # sin WiFi RAM: [= ] 6.6% (used 21464 bytes from 327680 bytes) Flash: [== ] 20.6% (used 269437 bytes from 1310720 bytes) $ pio run # con WiFi.begin() RAM: [= ] 13.3% (used 43424 bytes from 327680 bytes) Flash: [====== ] 55.3% (used 724865 bytes from 1310720 bytes)

Con WiFi: +21 kB de RAM estática y +445 kB de Flash (casi el triple).

Prompt para el asistente

1. Proyecto. Crea un proyecto nuevo de PlatformIO para esp32dev con Arduino, partiendo del programa del Ejemplo 01. 2. Firmware. Añade #include <WiFi.h> y WiFi.begin("Wokwi-GUEST", "") en setup(), agrupadas para compilar con y sin ellas. No cambies nada más: ni el GPIO 2, ni el período, ni la traza. Compila las dos versiones y copia las líneas RAM y Flash de cada una. 3. Simulación. Añade la simulación de Wokwi del Ejemplo 01 y comprueba que con WiFi el LED sigue conmutando. 4. Diagramas. En Excalidraw: el procedimiento de medida (compilar, anotar, añadir, recompilar, restar) y unas barras a escala con la RAM y la Flash de las dos versiones.

Por qué se pide así. Cambiar una sola cosa entre las dos construcciones hace que la resta mida la dependencia y nada más. El informe sale al enlazar: no hace falta grabar la placa.

Qué comprueba. Cada dependencia tiene un costo en memoria medible antes de grabar; el informe solo cuenta la RAM estática.

Pregunta de predicción: al añadir WiFi.begin(), ¿cuánto crecerán la RAM y la Flash del informe? La Flash casi se triplica y la RAM estática se duplica. Esa cifra no incluye los búferes que el WiFi reserva en el montón al arrancar, de modo que un firmware que compila con margen puede quedarse sin memoria en ejecución.

Para estudiar

En la práctica

RAM: SRAM reservada de forma estática (variables globales); no incluye pila ni montón. Flash: binario sobre la partición de aplicación de 1 310 720 bytes. En ejecución, ESP.getFreeHeap() da la SRAM libre real.

Dónde aparece

Al final de cada pio run, tras Checking size .pio/build/esp32dev/firmware.elf.

Errores frecuentes

  • Flash por encima del 100 %: el enlazado falla; se cambia board_build.partitions.
  • Leer el 13,3 % de RAM como margen garantizado.
