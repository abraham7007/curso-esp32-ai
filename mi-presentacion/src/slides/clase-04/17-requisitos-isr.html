04 · Interrupciones y eventos

Requisitos de una rutina de servicio

Definición

La rutina de servicio (ISR) se ejecuta en un contexto en el que el resto del sistema está detenido. Sus restricciones no son preferencias de estilo: incumplirlas produce reinicios y datos incoherentes.

  • Duración mínima. Mientras se ejecuta, nada más avanza y las demás interrupciones quedan pendientes.
  • Sin Serial.print(), delay() ni esperas. Bloquean con el sistema detenido.
  • Sin reserva dinámica. new, malloc y String usan un asignador que no es reentrante.
  • Variables compartidas volatile. Sin ese calificador el compilador puede cachearlas en un registro y el bucle no ve el cambio.
  • Acceso protegido. Si la variable ocupa más de una palabra, el bucle puede leerla a medio actualizar.
En la práctica

La rutina se marca con IRAM_ATTR para que su código resida en RAM interna y no dependa de la caché de la Flash.

rutina asociada a un pulsador Así no 
void alFlanco() {
  String msg = "pulso ";
  msg += String(millis());
  Serial.println(msg);
  delay(20);
  contador++;
}
Reserva dinámica, salida serie y espera bloqueante; contador tampoco es volatile.
rutina asociada a un pulsador Así sí 
volatile uint32_t pulsos = 0;
volatile bool hayEvento = false;

void IRAM_ATTR alFlanco() {
  pulsos++;
  hayEvento = true;
}
La rutina solo registra el evento. La interpretación y la salida por el puerto serie ocurren después, en el bucle.
