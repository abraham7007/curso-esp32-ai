01 · Sensores y diseño del driver

Definición y responsabilidad de un driver

Definición

Driver (controlador de dispositivo): capa que convierte entre el formato de datos del dispositivo y el formato que necesita la aplicación, sin incorporar lógica de aplicación. Traduce códigos del convertidor, registros o temporizaciones en magnitudes físicas; no decide qué se hace con ellas.

Driver con lógica dentro

SensorTemperatura.cpp Así no 
float SensorTemperatura::leer() {
  float t = convertir(analogRead(pin_));
  if (t > 40.0) activarAlarma();  return t;
}

El módulo del sensor decide si hay que activar una alarma. Cambiar el umbral obliga a tocar el driver, y el módulo no se puede reutilizar en otro proyecto donde 40 °C no signifique nada.

Driver sin lógica

SensorTemperatura.cpp · main.cpp Así sí 
float SensorTemperatura::leer() {
  return convertir(analogRead(pin_));
}
// main.cpp — la decisión vive aquí
if (sensor.leer() > kUmbral) alarma.encender();

El módulo entrega una temperatura en grados. Quién la compara, con qué umbral y con qué consecuencia es competencia de la capa de aplicación, que es la única que cambia entre proyectos.

Criterio operativo. Se elige el driver sin lógica: un driver no contiene ningún umbral ni ninguna decisión. La prueba es copiarlo a otro proyecto — si hubiera que cambiar un número que representa una decisión, esa decisión está en el sitio equivocado y pertenece a la capa de aplicación.
