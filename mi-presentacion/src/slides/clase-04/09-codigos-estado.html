Códigos de estado HTTP y peticiones sin respuesta

El código de estado lo envía el servidor. Si la respuesta no llega, no hay código: el fallo está en la red, el nombre o la conexión.

Pregunta de predicción: con el router desconectado de Internet y el ESP32 todavía unido al WiFi, ¿qué código de estado recibe el ESP32? Ninguno. Ningún servidor contestó, de modo que no puede haber un 4xx ni un 5xx; fallan el DNS o la conexión, y el monitor muestra «Error de conexión». El ejemplo 16 decide primero si hubo respuesta y, solo entonces, mira si el código es 200.

La reacción depende del origen del fallo. Un 4xx indica un error en la petición, y repetirla sin cambios devuelve el mismo código. Un 5xx o una petición sin respuesta pueden resolverse en un intento posterior. Ante un 429 se reduce la frecuencia de las consultas.

Para estudiar

En la práctica

HTTPClient señala la ausencia de respuesta con un número negativo en lugar del código de estado: −1 si la conexión no llega a abrirse (DNS incluido), −5 si se pierde a mitad de la respuesta y −11 si se abrió y la respuesta no llegó en 5000 ms, plazo ajustable (núcleo Arduino-ESP32 2.0.17). Su texto («connection refused», «read Timeout») es el que imprime el monitor.

Dónde aparece

Ejemplo 16, con las tres ramas; ejemplo 18, con un mensaje propio para 401, 404 y 429.

Errores frecuentes

  • Tratar igual todo código distinto de 200, con lo que un 401 se reintenta sin fin o un 429 se ignora.
  • Buscar el fallo en el servidor cuando no hubo respuesta: el problema está antes, en la red o en el nombre.
