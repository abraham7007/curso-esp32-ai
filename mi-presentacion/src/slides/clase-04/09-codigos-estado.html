03 · HTTP

Códigos de estado HTTP y códigos negativos de HTTPClient

Los códigos positivos los envía el servidor. Los negativos los genera HTTPClient cuando la respuesta no llega.

Pregunta de predicción: con el router desconectado de Internet y el ESP32 todavía unido al WiFi, ¿qué número devuelve http.GET()? Devuelve −1. Ningún servidor contestó, de modo que no puede haber un 4xx ni un 5xx; fallan el DNS o la conexión. El ejemplo 16 comprueba primero httpCode > 0 y, dentro de esa rama, si el código es 200.

La reacción depende del origen del fallo. Un 4xx indica un error en la petición, y repetirla sin cambios devuelve el mismo código. Un 5xx o un código negativo pueden desaparecer en un intento posterior. Ante un 429 se reduce la frecuencia de las consultas.

Para estudiar

En la práctica

Constantes de HTTPClient.h (núcleo Arduino-ESP32 2.0.17): HTTP_CODE_OK = 200, HTTPC_ERROR_CONNECTION_REFUSED = −1, HTTPC_ERROR_CONNECTION_LOST = −5, HTTPC_ERROR_READ_TIMEOUT = −11. La espera de respuesta es de 5000 ms por defecto; se cambia con http.setTimeout(ms).

Por qué −1 también cubre el DNS

Cuando el nombre no se resuelve, la conexión no llega a abrirse y http.GET() devuelve −1, el mismo código que con el servidor caído.

Errores frecuentes

Tratar igual todo código distinto de 200, con lo que un 401 se reintenta sin fin o un 429 se ignora.
