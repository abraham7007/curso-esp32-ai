Resumen de la sesión 4

  1. Enlace

    El ESP32 se conecta como cliente en 2,4 GHz, con un tiempo de espera de 20 s para la conexión WiFi.

  2. Petición

    DNS, TCP, TLS y GET; sin respuesta del servidor no hay código de estado.

  3. Datos

    Los campos útiles del JSON pasan a variables; red y pantalla se actualizan con frecuencias distintas.

  4. Claves

    Verificación previa con curl, intervalo según la cuota y clave fuera del código, enviada por HTTPS.

  5. Robustez

    Una consulta fallida se diagnostica capa a capa con el monitor serie; el último dato se muestra con su edad.

Términos clave

  • Estación (station, STA): el ESP32 se une a una red ajena como cliente.
  • RSSI: potencia recibida en dBm; un valor más cercano a 0 indica más señal.
  • DNS: traduce un nombre (api.coingecko.com) a una dirección IP.
  • NAT: el router comparte una IP pública; desde fuera no se puede iniciar una conexión hacia el ESP32.
  • Endpoint: ruta concreta de una API que responde a una petición.
  • Código de estado: 2xx éxito, 4xx error de la petición, 5xx error del servidor; negativo, error local de HTTPClient.
  • TLS: cifra la conexión de HTTPS; sin certificado cargado no verifica al servidor.
  • Deserializar: convertir el texto JSON en un documento navegable.
  • Cuota (rate limit): peticiones permitidas por minuto o por mes; superarla da 429.
  • Clave de API (API key): identifica la cuenta; se guarda fuera del repositorio.
