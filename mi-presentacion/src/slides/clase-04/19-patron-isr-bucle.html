04 · Interrupciones y eventos

Patrón: la rutina registra, el bucle procesa

Definición

La rutina de servicio hace lo mínimo: incrementar un contador, guardar una marca de tiempo o encolar el evento. Todo el procesamiento (conversión, salida por el puerto serie, escritura en pantalla) ocurre en el bucle principal, que lee esa información cuando le corresponde.

En la práctica

Leer y bajar la bandera debe ser atómico respecto de la interrupción: se delimita con portENTER_CRITICAL(&mux) / portEXIT_CRITICAL(&mux). Con un solo bool, el riesgo se limita a perder un evento simultáneo.

En la Sesión 6 este mismo patrón se traslada a una tarea de FreeRTOS: la rutina notifica a la tarea en lugar de marcar una bandera, y el bucle deja de ser el único lugar donde se procesa.

src/main.cpp · registro en la rutina, proceso en el bucle 
volatile bool     hayEvento = false;
volatile uint32_t msEvento  = 0;

void IRAM_ATTR alFlanco() {
  msEvento  = millis();
  hayEvento = true;
}

void loop() {
  if (hayEvento) {
    hayEvento = false;
    Serial.printf("[EVENTO] ms=%lu\n", msEvento);
    registrarPulsacion(msEvento);
  }

  // el resto de módulos sigue avanzando
  sensores.update();
  pantalla.update();
}
La bandera se baja antes de procesar: si llega otro evento durante el procesamiento, vuelve a subir y el bucle lo atiende en la iteración siguiente en lugar de descartarlo.
