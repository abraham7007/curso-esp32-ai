Delimitación de una trama propia con cabecera y longitud

La trama 0 del ejemplo 13, byte a byte: el receptor busca AA, lee la longitud y sabe cuántos bytes esperar.

Pregunta de predicción, antes de comentar la figura: si el receptor se conecta a mitad de una transmisión, ¿cómo identifica el primer byte de un mensaje? Respuesta: busca AA y descarta lo anterior (3F 12). Luego lee el identificador y la longitud: 06 indica que siguen seis bytes de carga y uno de verificación, así que la carga puede llevar cualquier valor, incluso un AA. Antes del paso, pedir que calculen el checksum; el paso muestra el del ejemplo 13: suma de identificador, longitud y carga, sin la cabecera, de la que se conserva el byte bajo.

Para estudiar

En la práctica

Emisor: escribe 0xAA, el identificador, la longitud, la carga y el checksum, sumado en una variable de un byte (el desbordamiento hace el módulo 256). Receptor: una máquina de estados, esperando cabecera → leyendo identificador → leyendo longitud → leyendo carga → leyendo checksum.

Dónde aparece

Ejemplo 13: monitor Tx: [AA 00 06 48 6F 6C 61 20 30 DA] -> ACEPTADA; diagrama diagrama-trama-bytes.excalidraw.

Errores frecuentes

  • Usar el fin de línea como fin de trama binaria: 0x0A puede ser un dato.
  • Sin longitud, el receptor no sabe dónde acaba la carga.
